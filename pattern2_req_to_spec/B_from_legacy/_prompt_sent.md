# 数値処理ライブラリ numlib 機能仕様書（抜粋）

版数 0.9 ／ 作成日 2026-09-25 ／ 制御ソフト第二課

※ AI検証用のダミー資料。実在の製品・顧客とは無関係

# 1. 概要と前提

- 目的：組込み制御ソフト向けの小規模な数値処理ライブラリ
- 対象言語：C（C99準拠）。コンパイラ警告ゼロ（-Wall -Wextra）
- 制約
- 動的メモリ確保（malloc/free）は使用しない
- スレッドセーフ非対応（呼び出し側で排他）
- 依存ヘッダは &lt;stddef.h&gt; &lt;stdint.h&gt; のみ
- 浮動小数点は double。printf 等の標準I/Oは使わない
- 提供関数
- bubble\_sort\_i32 … 32bit整数配列の昇順ソート（バブルソート・安定）
- gauss\_eliminate … 連立一次方程式 Ax = b を掃き出し法で解く

# 2. 関数仕様：bubble\_sort\_i32

| 項目     | 内容                                               |
|--------|--------------------------------------------------|
| シグネチャ  | int bubble_sort_i32(int32_t *arr, size_t n);     |
| 目的     | arr[0..n-1] を昇順に並べ替える。等しい値の相対順序は保つ（安定ソート）        |
| 引数 arr | 整列対象の配列。n > 0 のとき非NULL であること                     |
| 引数 n   | 要素数。0 以上。n <= 1 のときは何もしない                        |
| 戻り値    | 0：成功 ／ -1：引数不正（n > 0 かつ arr == NULL）             |
| 事後条件   | 成功時、すべての i について arr[i] <= arr[i+1]。要素の多重集合は不変    |
| 計算量    | 時間 O(n^2)、追加メモリ O(1)。既ソート入力では 1 パスで終了する（早期終了フラグ） |

# 3. 関数仕様：gauss\_eliminate（掃き出し法）

| 項目    | 内容                                                              |
|-------|-----------------------------------------------------------------|
| シグネチャ | int gauss_eliminate(double *a, double *b, double *x, size_t n); |
| 目的    | n×n 行列 A と右辺 b から Ax = b の解 x を求める（部分ピボット選択付き掃き出し法）             |
| 引数 a  | n×n 行列を行優先（row-major）で格納した配列。非NULL。作業領域として破壊してよい                |
| 引数 b  | 右辺ベクトル（長さ n）。非NULL。作業領域として破壊してよい                                |
| 引数 x  | 解の出力先（長さ n）。非NULL                                               |
| 引数 n  | 次元。1 以上 16 以下（NUMLIB_MAX_DIM = 16）                              |
| 戻り値   | 0：成功 ／ -1：引数不正（NULL または n == 0）／ -2：特異行列 ／ -3：n > 16            |
| 特異判定  | ピボット選択後の &#124;a[k][k]&#124; < 1e-12 のとき特異とみなす（EPS はヘッダで定数定義）   |
| 精度    | 条件数 1e6 以下の行列で相対誤差 1e-9 以内                                      |

# リングバッファ（ring_buffer）仕様書

**バージョン**: 1.0
**作成日**: 2026-07-26
**対象言語**: C（C99準拠）
**用途**: ローカルLLM（Nemotron-3-Super / gemma3 / gpt-oss-120b 等）による関数レベル単体試験自動生成のサンプル題材

---

## 1. 概要

固定長のバイトデータ（`uint8_t`）を格納するFIFO方式のリングバッファ（循環バッファ）である。組込み系におけるシリアル通信の受信バッファ、センサーデータのバッファリング等を想定した最小構成のライブラリとする。

- 動的メモリ確保は行わない（バッファ実体は呼び出し側が用意）
- スレッドセーフではない（呼び出し側で排他制御すること）
- 依存ヘッダは `<stddef.h>` `<stdint.h>` `<stdbool.h>` のみ

---

## 2. データ構造

```c
#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    uint8_t *buffer;   /* 呼び出し側が確保したバッファ領域へのポインタ */
    size_t   capacity; /* バッファの総容量（バイト数） */
    size_t   head;     /* 次に読み出す位置（0 <= head < capacity） */
    size_t   tail;     /* 次に書き込む位置（0 <= tail < capacity） */
    size_t   count;    /* 現在格納されている要素数（0 <= count <= capacity） */
} ring_buffer_t;
```

### 設計上の要点

- `head` / `tail` に加えて **`count` を明示的に保持する方式** を採用する。
  - これにより `head == tail` が「空」なのか「満杯」なのかを `count` で一意に判定できる。
  - 「1スロット犠牲方式（capacity-1しか使えない方式）」は採用しない。**capacity 全部を使い切れる**。
- リングバッファ本体（`ring_buffer_t`）と、その実データ領域（`uint8_t` 配列）は分離する。

---

## 3. API 一覧

| # | 関数名 | 概要 |
|---|--------|------|
| 1 | `rb_init` | 初期化 |
| 2 | `rb_push` | 1バイト書き込み（末尾追加） |
| 3 | `rb_pop` | 1バイト読み出し（先頭取り出し） |
| 4 | `rb_peek` | 1バイト参照（先頭を取り出さずに見る） |
| 5 | `rb_clear` | 中身を空にする |
| 6 | `rb_is_empty` | 空かどうか判定 |
| 7 | `rb_is_full` | 満杯かどうか判定 |
| 8 | `rb_count` | 現在の格納要素数を取得 |
| 9 | `rb_capacity` | バッファ容量を取得 |
| 10 | `rb_free_space` | 空き容量を取得 |

---

## 4. 各関数仕様

### 4.1 `rb_init` — 初期化

```c
int rb_init(ring_buffer_t *rb, uint8_t *buffer, size_t capacity);
```

**目的**: リングバッファ構造体を初期化する。

**引数**:
| 引数 | 意味 | 制約 |
|------|------|------|
| `rb` | 初期化対象の構造体ポインタ | 非NULL |
| `buffer` | データ格納用のバッファ領域 | 非NULL・少なくとも `capacity` バイト確保済み |
| `capacity` | バッファ容量（バイト数） | 1以上 |

**戻り値**:
- `0` : 成功
- `-1` : 引数不正（`rb == NULL` / `buffer == NULL` / `capacity == 0`）

**事後条件**（成功時）:
- `rb->buffer == buffer`
- `rb->capacity == capacity`
- `rb->head == 0`
- `rb->tail == 0`
- `rb->count == 0`

---

### 4.2 `rb_push` — 書き込み

```c
int rb_push(ring_buffer_t *rb, uint8_t data);
```

**目的**: バッファ末尾に1バイト追加する。

**引数**:
| 引数 | 意味 | 制約 |
|------|------|------|
| `rb` | 対象リングバッファ | 非NULL・初期化済み |
| `data` | 書き込むデータ | 任意（0x00〜0xFF） |

**戻り値**:
- `0` : 成功
- `-1` : 引数不正（`rb == NULL`）または満杯（`count == capacity`）

**事後条件**（成功時）:
- `rb->buffer[tail_old] == data`
- `rb->tail == (tail_old + 1) % capacity`（**ラップアラウンドあり**）
- `rb->count == count_old + 1`
- `rb->head` は変化しない

---

### 4.3 `rb_pop` — 読み出し

```c
int rb_pop(ring_buffer_t *rb, uint8_t *data);
```

**目的**: バッファ先頭から1バイト取り出す。

**引数**:
| 引数 | 意味 | 制約 |
|------|------|------|
| `rb` | 対象リングバッファ | 非NULL・初期化済み |
| `data` | 読み出したデータの格納先 | 非NULL |

**戻り値**:
- `0` : 成功
- `-1` : 引数不正（`rb == NULL` / `data == NULL`）または空（`count == 0`）

**事後条件**（成功時）:
- `*data == rb->buffer[head_old]`
- `rb->head == (head_old + 1) % capacity`（**ラップアラウンドあり**）
- `rb->count == count_old - 1`
- `rb->tail` は変化しない

**注意**: 失敗時（空・引数不正）は `*data` の内容は保証しない。

---

### 4.4 `rb_peek` — 参照のみ

```c
int rb_peek(const ring_buffer_t *rb, uint8_t *data);
```

**目的**: バッファ先頭のデータを取り出さずに参照する。

**引数**:
| 引数 | 意味 | 制約 |
|------|------|------|
| `rb` | 対象リングバッファ | 非NULL・初期化済み |
| `data` | 読み出したデータの格納先 | 非NULL |

**戻り値**:
- `0` : 成功
- `-1` : 引数不正（`rb == NULL` / `data == NULL`）または空

**事後条件**（成功時）:
- `*data == rb->buffer[rb->head]`
- **`rb->head` / `rb->tail` / `rb->count` は変化しない**（副作用なし）

---

### 4.5 `rb_clear` — 消去

```c
void rb_clear(ring_buffer_t *rb);
```

**目的**: バッファを空の状態に戻す。

**引数**:
| 引数 | 意味 | 制約 |
|------|------|------|
| `rb` | 対象リングバッファ | 非NULL・初期化済み |

**戻り値**: なし

**事後条件**:
- `rb->head == 0`
- `rb->tail == 0`
- `rb->count == 0`
- `rb->buffer` および `rb->capacity` は変化しない
- **バッファ実体のメモリ内容はクリアしない**（残存データはそのまま）

**注意**: `rb == NULL` の場合は何もしない（クラッシュしない）。

---

### 4.6 状態問い合わせ関数群

```c
bool   rb_is_empty  (const ring_buffer_t *rb);
bool   rb_is_full   (const ring_buffer_t *rb);
size_t rb_count     (const ring_buffer_t *rb);
size_t rb_capacity  (const ring_buffer_t *rb);
size_t rb_free_space(const ring_buffer_t *rb);
```

| 関数 | 戻り値 | `rb == NULL` の場合 |
|------|--------|---------------------|
| `rb_is_empty`   | `count == 0` なら `true` | `true` を返す |
| `rb_is_full`    | `count == capacity` なら `true` | `false` を返す |
| `rb_count`      | 現在の格納要素数 | `0` を返す |
| `rb_capacity`   | 総容量 | `0` を返す |
| `rb_free_space` | `capacity - count` | `0` を返す |

これらの関数はすべて**副作用なし**（`rb` の内容を変更しない）。

---

## 5. エラー処理方針

- 戻り値方式で通知する（`0` = 成功、`-1` = 失敗）。`errno` は使用しない。
- NULLポインタ引数はエラーとして扱い、クラッシュせずに `-1` を返す（`rb_clear` を除く）。
- 動的メモリ確保・解放は一切行わない。
- ログ出力・アサーション（`assert`）は行わない。

---

## 6. スレッドセーフ性・非機能要件

| 項目 | 仕様 |
|------|------|
| スレッドセーフ | **非対応**。呼び出し側で排他制御すること |
| 割り込みセーフ | **非対応**。ISRから呼ぶ場合は排他必須 |
| 再入可能性 | 別インスタンスに対してなら再入可 |
| ヒープ使用 | なし |
| スタック使用 | 数十バイト程度（各関数とも定数時間） |
| 計算量 | 全関数 O(1) |

---

## 7. 使用例

```c
#include "ring_buffer.h"
#include <stdio.h>

int main(void) {
    uint8_t storage[8];
    ring_buffer_t rb;

    rb_init(&rb, storage, sizeof(storage));

    rb_push(&rb, 'A');
    rb_push(&rb, 'B');
    rb_push(&rb, 'C');

    uint8_t v;
    while (rb_pop(&rb, &v) == 0) {
        putchar(v);   /* → A B C の順で出力 */
    }
    return 0;
}
```

## 8. 単体試験観点（テスト設計者向け参考）

LLMによる試験生成時に**最低限カバーすべきエッジケース**を以下に列挙する。

### 8.1 `rb_init`
- [ ] 正常系：capacity=1, 2, 8, 256 で初期化成功、head/tail/count が0
- [ ] 異常系：`rb == NULL` で `-1`
- [ ] 異常系：`buffer == NULL` で `-1`
- [ ] 異常系：`capacity == 0` で `-1`

### 8.2 `rb_push`
- [ ] 空 → 1件push → count=1, tail=1
- [ ] capacity 分だけpushして満杯にできる（`-1` にならない）
- [ ] 満杯状態からさらにpushで `-1`、状態は変化しない
- [ ] `rb == NULL` で `-1`

### 8.3 `rb_pop`
- [ ] push→pop で同じ値が取れる（FIFO）
- [ ] 複数push→複数popで順序が保たれる
- [ ] 空状態でpop → `-1`、data不変
- [ ] `rb == NULL` / `data == NULL` で `-1`
- [ ] 全件popで空に戻る、count=0

### 8.4 `rb_peek`
- [ ] peek後もheadが動かない、countも減らない
- [ ] 連続2回peekで同じ値が返る
- [ ] 空でpeek → `-1`
- [ ] `rb == NULL` / `data == NULL` で `-1`

### 8.5 ラップアラウンド（**最重要**）
- [ ] capacity=4 で push×3 → pop×2 → push×3 → tailがラップする
- [ ] ラップ後にpopした結果が挿入順どおりであること
- [ ] `head` / `tail` が capacity を超えないこと
- [ ] 何度でも周回可能（100周分push/popしても壊れない）

### 8.6 満杯・空の区別
- [ ] capacity=1 で push 1回 → `is_full == true` かつ `is_empty == false`
- [ ] capacity=1 で push 1回 → pop 1回 → `is_empty == true`
- [ ] `head == tail` かつ `count == 0` は空
- [ ] `head == tail` かつ `count == capacity` は満杯（両者を混同しないこと）

### 8.7 `rb_clear`
- [ ] pushして中身がある状態でclear → count=0, head=0, tail=0
- [ ] clear後に再度push/popが正常動作
- [ ] `rb == NULL` でクラッシュしない

### 8.8 状態問い合わせ
- [ ] 初期化直後：`is_empty==true`, `is_full==false`, `count==0`, `free_space==capacity`
- [ ] 満杯時：`is_empty==false`, `is_full==true`, `free_space==0`
- [ ] `rb == NULL` の各関数戻り値（表の通り）

### 8.9 境界値
- [ ] capacity=1 での全操作
- [ ] capacity=SIZE_MAX級（現実的にはテストしない、コンパイル可能性のみ）
- [ ] data=0x00, 0xFF, 0x55, 0xAA など特徴的な値でのpush/pop
