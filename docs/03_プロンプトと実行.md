# プロンプトと実行コマンド（OpenCode ＋ Nemotron-3-Super）

指示文はそのまま流用できる。

## プロンプト

| 用途 | ファイル | 入力 → 出力 |
|---|---|---|
| 要件（数行）→ 仕様書 | [A](../pattern2_req_to_spec/prompts/A_要件から仕様書.md) | 要件＋見本 → 10 章の仕様書 |
| 要件定義書（PPT）→ 仕様書 | [A2](../pattern2_req_to_spec/prompts/A2_要件定義パワポから仕様書.md) | 変換した要件定義書＋見本 → 10 章＋要件トレース表 |
| 既存資料 → 仕様書 | [B](../pattern2_req_to_spec/prompts/B_既存資料から仕様書.md) | 変換した PPT/Excel＋図の OCR＋見本 → 10 章＋Mermaid 図 |
| 仕様書 → 実装・試験 | [C](../pattern2_req_to_spec/prompts/C_仕様書から実装.md) | SPEC.md＋AGENTS.md → コード・テスト・結果 MD |

## 実行

```bash
# 仕様書を書かせる（ファイルを触らない plan エージェントで）
opencode run --agent plan -m openrouter/nvidia/nemotron-3-super-120b-a12b "$(cat _prompt_sent.md)" < /dev/null > out.txt

# 実装させる（pattern3_impl の中で。編集とシェルを許可した build エージェント）
cd pattern3_impl && opencode run -m openrouter/nvidia/nemotron-3-super-120b-a12b "$(cat ../pattern2_req_to_spec/prompts/C_仕様書から実装.md)" < /dev/null
make test && make coverage         # 人が同じコマンドで再確認
```

オンプレでは `-m` を vLLM 上の Nemotron に変えるだけ。指示文・AGENTS.md・Makefile はそのまま。

## 注意（6つ）

1. スクリプトやバックグラウンドから呼ぶときは **`< /dev/null` を付ける**（標準入力待ちで無言で止まる）
2. 仕様書を書かせるときは **`--agent plan`**（既定の build はファイルを作りに行く）
3. 実装させるときの権限は [opencode.json](../opencode.json) で絞る（`rm -rf` / `sudo` / `git push` / ネットワーク / パッケージ導入を拒否）
4. **ビルド・試験・カバレッジの手順は Makefile に固定し、AI に書かせない**。失敗の原因がコードか手順か切り分けられる
5. **セッションのタイトル生成に別の小モデルが呼ばれる**（ログに `google/gemini-3.8-flash`）。オンプレで外部に一切出したくない場合は、設定の `small_model` もローカルのモデルにする
6. **`AGENTS.md` はどのエージェント・どのモデルにも自動で読み込まれる。** 仕様書を書かせる `plan` エージェントにも入る。モデル比較のように「同じ入力」を保証したい実験は、AGENTS.md の無い別ディレクトリで実行する
