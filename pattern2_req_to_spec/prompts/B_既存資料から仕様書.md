これを【見本】と同じ章立て・粒度の、AIコーディングエージェントがそのまま実装と単体試験生成に使える仕様書に再構成してください。

出力ルール:
- 章立ては見本どおり: 1.概要 / 2.データ構造・定数 / 3.API一覧 / 4.各関数仕様 / 5.エラー処理方針 / 6.非機能要件 / 7.使用例 / 8.単体試験観点 / 9.ファイル構成 / 10.改訂履歴
- 既存資料に書いてあることは一字一句を尊重し、勝手に変えない
- 既存資料に無いが実装に必要な情報（失敗時の状態保証、境界条件、定数の置き場所など）は補ってよいが、補った箇所には必ず【要確認】と付ける。推測で確定させない
- OCRで読んだ図の文字は誤認識を含む（例: `1allIk］` は `|a[i][k]|` の誤読）。既存資料の本文と突き合わせて意味を復元し、処理フローは Mermaid の flowchart として書き直す。復元に自信がない箇所は【要確認】
- 各関数は「シグネチャ」「目的」「引数の表」「戻り値」「事後条件」「失敗時の状態」を必ず書く
- 単体試験観点は既存資料の T01〜T12 を引き継ぎ、足りない境界値があれば追加して番号を続ける
- Cの実装コードは書かない
- ツールやファイル操作は使わず、Markdown本文だけを返答する
